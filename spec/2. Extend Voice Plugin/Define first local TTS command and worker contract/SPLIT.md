# Split: First Local TTS Command and Worker Contract

## 1. Purpose

Break the approved TTS command and worker contract into implementation-sized slices.

This split plan keeps each slice local to the voice plugin and avoids playback, streaming, recorder changes, STT behavior changes, consumer migration, or broad engine abstractions.

## 2. Implementation Slices

### Slice 1: Rust Contract Models

Files:

- `tauri-plugin-voice/src/models.rs`
- `tauri-plugin-voice/tests/smoke_contract.rs`

Work:

- Add `SynthesizeSpeechRequest`.
- Add `SynthesizeSpeechResponse`.
- Add an audio format representation only if it improves readability.
- Add serialization tests for request and response camelCase fields.

Validation:

- Rust contract tests pass.
- Existing STT serialization tests still pass.

### Slice 2: TTS Output Policy

Files:

- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/tests/smoke_contract.rs`, or a focused unit-test file if local test patterns support it.

Work:

- Add TTS constants for default model, voice, format, output subdirectory, text limit, and speed range.
- Add direct validation for text, model, voice, language, speed, and output path fields.
- Add app-data default output path resolution under `APP_DATA_DIR/tts/output`.
- Reject conflicting `outputPath` and `outputDir`.

Validation:

- Empty text is rejected.
- Unsupported model is rejected.
- Unsupported voice is rejected.
- Invalid speed is rejected.
- Conflicting output fields are rejected.
- Default output path uses the TTS app-data directory.

### Slice 3: TTS Worker Ownership

Files:

- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/src/models.rs`, only if worker response structs are needed.

Work:

- Add a TTS worker slot separate from the STT worker.
- Spawn the TTS worker using the shared Python binary.
- Wait for the TTS ready line.
- Clear the TTS worker slot on startup failure, I/O failure, timeout, or disconnect.
- Keep implementation direct without a generic engine dispatcher.

Validation:

- Missing Python binary returns not-ready.
- Missing worker script returns generation failed.
- Startup timeout returns not-ready.
- Health can report an absent or failed TTS worker without affecting STT worker ownership.

### Slice 4: Python TTS Worker

Files:

- `tauri-plugin-voice/scripts/tts_worker.py`

Work:

- Add a persistent worker parallel to the STT worker shape.
- Accept `--model`.
- Emit download and preload progress when supported.
- Emit a ready line after model preload.
- Read newline-delimited JSON synthesis requests.
- Generate one WAV file per request.
- Return compact JSON success or typed error responses.

Validation:

- Worker starts and emits ready for the approved model.
- Worker emits valid progress JSON lines.
- Worker writes the requested WAV path on success.
- Worker returns typed error JSON on invalid runtime failures.

### Slice 5: Command Wiring

Files:

- `tauri-plugin-voice/src/commands.rs`
- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/src/lib.rs`

Work:

- Add the `synthesize_speech` Tauri command.
- Delegate through `app.tauri_plugin_voice()`.
- Gate the command on TTS readiness only.
- Send one validated request to the TTS worker.
- Parse one response from the worker.
- Verify the output path exists before returning.

Validation:

- Command compiles.
- Successful worker response maps to `SynthesizeSpeechResponse`.
- Worker error response maps to generation failed.
- Worker timeout clears the TTS worker slot.

### Slice 6: Progress and Health

Files:

- `tauri-plugin-voice/src/models.rs`
- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/tests/smoke_contract.rs`

Work:

- Publish TTS progress events with `engine = "tts"`.
- Keep the existing `tauri-voice-plugin://model-progress` channel.
- Extend `voice_health` with TTS diagnostics when implementation starts.
- Ensure TTS readiness does not block aggregate readiness unless TTS is configured as required.

Validation:

- Progress event serialization includes `engine = "tts"`.
- STT progress event shape remains unchanged except existing engine-aware behavior.
- `voice_health` reports TTS readiness separately.
- STT-dependent commands do not require TTS readiness.

### Slice 7: Guest API and Permissions

Files:

- `tauri-plugin-voice/guest-js/index.ts`
- `tauri-plugin-voice/permissions/default.toml`
- `tauri-plugin-voice/permissions/autogenerated/commands/synthesize_speech.toml`
- Generated schemas, if produced by the Tauri plugin workflow.

Work:

- Add TypeScript request and response types.
- Add `synthesizeSpeech`.
- Invoke `plugin:voice|synthesize_speech`.
- Add `allow-synthesize-speech`.
- Include the command in default permissions only if this is approved as a default API.

Validation:

- Guest package type-checks.
- Permission metadata contains the new command.
- Generated schemas include the new command when regenerated.

### Slice 8: Documentation

Files:

- `tauri-plugin-voice/README.md`
- `tauri-plugin-voice/USAGE.md`, if existing usage docs remain the public integration guide.

Work:

- Document `synthesizeSpeech`.
- Document file-output-only behavior.
- Document default model, voice, output format, and output location.
- Document that playback and streaming are not part of v1.

Validation:

- Docs match implemented request and response names.
- Docs do not promise playback, streaming, voice cloning, or conversation orchestration.

## 3. Recommended Execution Order

1. Rust contract models.
2. Output policy.
3. TTS worker ownership.
4. Python TTS worker.
5. Command wiring.
6. Progress and health.
7. Guest API and permissions.
8. Documentation.

## 4. Done Criteria

The implementation can be considered complete when:

- `synthesize_speech` is registered under `plugin:voice|synthesize_speech`.
- The command returns a local WAV path.
- Request validation follows the approved contract.
- Unsupported models and voices fail clearly.
- TTS worker startup, success, error, timeout, and disconnect behavior are handled.
- TTS progress events include `engine = "tts"`.
- `voice_health` reports TTS readiness separately.
- Existing STT behavior remains intact.
- Focused Rust tests and available package checks pass.
- The user confirms validation.
