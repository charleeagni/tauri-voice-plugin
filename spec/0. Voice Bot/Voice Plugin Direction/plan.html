SCOPE.md · canonical
D · 01

Visible state machine.

All plugin states are externally observable. No opaque sub-states, no hidden intermediates. Hosts can subscribe to the full state stream.

D · 02

Event-out, command-in handoff.

Plugin emits transcript via voice://handoff. Host returns a single tagged respond command keyed on interactionId.

D · 03

Schema-extensible, not runtime-composable.

Return command carries speak + continue today. New directives extend the schema in future revisions — hosts never compose directive lists at runtime.

D · 04

Intermediate states declared at config time.

Hosts declare custom overlay states at plugin init. Runtime injection is rejected. The plugin owns transitions; the host owns views.

D · 05

Plugin is stateless across turns.

Conversation context lives in the host backend. Multi-turn re-engagement is a fresh startListening call — context never threads through the plugin.

D · 06

Overlay stays in the recorder bridge.

No ownership move this cycle. The contract defined here is overlay-implementation-agnostic and survives a future move.

Plumbing.

Make plugin state externally observable. No new semantics — pure visibility plumbing that every later phase depends on.

Rename phase enum values to Idle / Listening / Capturing / Transcribing. Mirror in TS bindings.

Add a live "Plugin State" badge subscribed to CHANNELS.STATE.

Event log panel

Append-only, timestamped log of every state-change event. Foundation for debugging every later slice.
Any flow produces a complete, scannable event sequence in the log panel.
02
Phase · Boundary

Handoff contract.

Introduce HandedOff as a real state. Emit the transcript on a dedicated event channel. Surface interactionId in the UI so every later slice can address an interaction.

4 slices· 04 → 07
slice 04
RUST

HandedOff state

After Transcribing, plugin enters HandedOff and holds for a default 30s before returning to Idle.
State badge sits on HandedOff for 30s after a recording before returning to Idle.
slice 05
APP

HandedOff overlay styling

Add the HandedOff phase to the overlay window with placeholder "Awaiting host…".
Overlay window stays visible with the placeholder after transcription completes.
slice 06

Handoff event with interactionId

slice 07
APP

Display interactionId

Track and render the active interactionId next to the state badge. Clear on Idle.

03
Phase · Contract

Return command.

Wire the host's response: respond with continue and speak directives, stale-ID rejection, and a configurable handoff timeout.

6 slices· 08 → 13
slice 08
RUSTTSAPP

respond · continue: false

Add respond(interactionId, {continue:false}). Validates ID; transitions HandedOff → Idle.
"End Interaction" button closes the overlay after a recording.
slice 09
RUSTAPP

respond · continue: true

Re-arm listening with a fresh interactionId. Same entry point as startListening.
"Continue" button returns the overlay to Listening with a new ID.
slice 10
RUST

Reject stale interactionId

Typed error when respond is called with an unknown or expired ID. No state change.
Clicking End after the handoff timeout surfaces the stale-ID error in the log.
slice 11
RUSTTSAPP

speak directive

Optional speak:{text, voice?, model?} routes to the existing TTS streaming pipeline. continue applies after playback.
"Speak then End" plays synthesized response, then closes the overlay.
slice 12
RUSTAPP

speak + continue:true chain

Sequence speak → re-arm cleanly with no playback/listening races.
"Speak then Continue" plays TTS, then overlay returns to Listening with new ID.
slice 13
RUSTTSAPP

Configurable handoff timeout

Accept optional handoffTimeoutMs on startListening. Emit handoff_timeout event on expiry.
Set 5s in the example app; HandedOff auto-returns to Idle in 5s, event logged.
04
Phase · Demo · headline arc

Overlay injection.

Hosts declare custom overlay states at config time and supply React components for each. The plugin emits, the overlay resolves and renders — the reusability proof.

6 slices· 14 → 19
slice 14
RUSTTSAPP

Declared states at init

Accept declaredStates:[{name, timeoutMs}] at plugin init. Expose listDeclaredStates().
App.jsx declares states and renders the list returned by the new command.
slice 15
RUSTAPP

Reject runtime injection

Test-only guard command always returns RuntimeInjectionRejected. Enforces the config-time invariant.
"Try Runtime Register" button shows the typed error in the log.
slice 16
RUSTTSAPP

transitionToState directive

"Show Thinking" button moves the state badge to Thinking.
slice 17
RUSTTS

render_declared_state event

On entering a declared state, emit voice://render-declared-state with state name + ID.
Event appears in the log panel with the correct declared-state name.
Headline
slice 18
APP

Host-supplied React component renders inside the overlay.

Define a host-side registry mapping declared state name → React component. The overlay subscribes to render-declared-state, resolves the registered component, and mounts it inside the existing overlay shell. The example app ships a <Thinking /> component for the "Thinking" state.
After "Show Thinking", the overlay window actually renders the host's <Thinking /> component — not a placeholder. This is the reusability proof for the entire project.
slice 19
RUST

Auto-exit declared state

Exit on next respond or when declared timeoutMs elapses. Emit state-change on exit.
After "Show Thinking", a respond({continue:false}) exits cleanly. Timeout path also verified.
05
Phase · Edges

Edge cases.

Close the corners: explicit Cancelled and Failed states with diagnostics, and a validation that re-engagement parity holds.

3 slices· 20 → 22
slice 20
RUSTAPP

Cancelled state

Mid-active cancellation transitions current state → Cancelled → Idle with state-change events.
"Cancel" mid-recording: badge briefly shows Cancelled before settling on Idle.
slice 21
RUST

Failed state with diagnostic

On unrecoverable failure: transition to Failed → Idle. Event carries a diagnostic field with a useful reason.
Configuring a bad STT model produces a Failed state with a readable diagnostic in the log.
slice 22
VALIDATION

Re-engagement parity

continue:true and an explicit startListening must produce identical state-change sequences. No new code unless parity is broken.
Side-by-side comparison in the log panel shows matching event sequences.

Implement strictly in order.

Each slice is independently shippable, validated in the example app at tauri-plugin-voice/examples/tauri-app/. Do not extend a slice's scope. The spec docs are the source of truth.
