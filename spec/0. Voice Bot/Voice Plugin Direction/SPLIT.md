# Split Plan: Voice Plugin Interface Boundary

## 1. Objective

Translate the locked scope and HLD into implementation phases that are individually testable in `tauri-plugin-voice/examples/tauri-app`. Each phase produces visible, interactive changes that can be validated before the next phase begins.

## 2. Tracked work units (Plane sub-tasks of CODIN-400)

Each phase below corresponds to a Plane sub-task. **Phases are the tracked implementation unit** — individual slices within a phase are implementation steps, not separately tracked items.

| Phase | Plane ticket | Slices |
|-------|-------------|--------|
| Phase 1 — Plumbing | CODIN-423 | 1–3 |
| Phase 2 — Handoff Contract | CODIN-424 | 4–7 |
| Phase 3 — Return Command | CODIN-425 | 8–13 |
| Phase 4 — Overlay Injection Demo | CODIN-426 | 14–19 |
| Phase 5 — Edge Cases | CODIN-427 | 20–22 |

Implement phases in order. Each phase must pass all its example-app validations before the next phase begins.

### 11. Slice 9: `respond` with `continue: true`

- "Continue" button in App.jsx returns the overlay to Listening; new `interactionId` appears.

### 12. Slice 10: Reject stale interactionId

- `tauri-plugin-voice/src/desktop.rs`

### 13. Slice 11: `speak` directive

- `tauri-plugin-voice/src/models.rs`

### 14. Slice 12: `speak` + `continue: true` chain

- Ensure speak-then-continue sequencing re-arms listening cleanly after playback ends.

### 15. Slice 13: Configurable handoff timeout

## Phase 4 — Overlay Injection Demo (CODIN-426)

- `tauri-plugin-voice/src/commands.rs`
- `tauri-plugin-voice/guest-js/index.ts`

- Store on plugin state; validate names are unique.
- Add `listDeclaredStates` command returning the configured set.

Validation:

### 17. Slice 15: Reject runtime injection

- `tauri-plugin-voice/src/commands.rs`
- `tauri-plugin-voice/src/error.rs`

Work:
- Add validation that rejects any attempt to register states outside of init.

Validation:

### 18. Slice 16: `transition_to_state` directive

Files:
- `tauri-plugin-voice/src/models.rs`
- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/guest-js/index.ts`

- Validate the name against declared states.

Validation:

### 19. Slice 17: `render_declared_state` event

Files:
- `tauri-plugin-voice/src/models.rs`
- `tauri-plugin-voice/src/desktop.rs`
- `tauri-plugin-voice/guest-js/index.ts`

Work:
- On entering a declared state, emit a `render_declared_state` event with the state name and `interactionId`.

Validation:
- Log panel in App.jsx shows the event with the correct name.

### 20. Slice 18: Host-supplied React component rendering

Files:
- `tauri-plugin-voice/examples/tauri-app/src/OverlayApp.jsx`
- `tauri-plugin-voice/examples/tauri-app/src/App.jsx` (or a shared registry module)

Work:
- Add a host-side registry in the overlay that maps declared state names to React components.
- On `render_declared_state`, resolve and render the registered component inside the overlay shell.
- Register a `<Thinking />` component for one declared state.

Validation:
- After sending `transitionToState: "Thinking"`, the overlay actually renders the `<Thinking />` component. **This is the headline success criterion.**

### 21. Slice 19: Auto-exit declared state

Files:
- `tauri-plugin-voice/src/desktop.rs`

Work:
- Exit the declared state on the next `respond`, or automatically when its `timeoutMs` elapses.
- Emit state-change event on exit.

Validation:
- Transition to Thinking, then send `respond {continue: false}`; overlay closes cleanly.
