# LLD: Control Recorder Overlay Hide Behavior for STT

## 1. Scope & Objective
Implement the logic to conditionally keep the recorder overlay visible after stopping a recording, allowing the STT pipeline to gracefully transition to the `Transcribing` phase without a UI flicker. An explicit `hide_overlay` command is added for manual dismissal.

## 2. Component Design & Changes

### 2.1. `tauri-plugin-recorder/src/models.rs`
- **`RecorderConfig` Struct:**
  - Add `pub hide_overlay_on_recording_stop: Option<bool>` to allow configuration without breaking existing serialization.

### 2.2. `tauri-plugin-recorder/src/desktop.rs`
- **`Recorder` Methods:**
  - Add `fn emit_state_event_with_sync(&self, event: &StateEvent, sync: bool)` to optionally skip the `sync_overlay_runtime_for_state` call.
  - Refactor `emit_state_event` to call `emit_state_event_with_sync(event, true)`.
  - In `stop_recording`:
    - Retrieve `hide_overlay_on_recording_stop` from the active runtime config (defaulting to `true`).
    - Use `self.emit_state_event_with_sync(&state_event, should_sync_overlay)` instead of `emit_state_event` so the native overlay is left open when `false`.
  - Add `pub fn hide_overlay(&self) -> crate::Result<()>`:
    - Explicitly calls `sync_overlay_shell(&self.app, OverlayRuntimePhase::Idle, DEFAULT_OVERLAY_URL)` (and respects `OverlayMode::Consumer` if needed) to force-hide the window.

### 2.3. `tauri-plugin-recorder/src/commands.rs` & `src/lib.rs`
- **`commands.rs`:**
  - Expose `#[tauri::command] pub async fn hide_overlay(recorder: tauri::State<'_, Recorder>) -> Result<()>`.
- **`lib.rs`:**
  - Add `hide_overlay` to the `generate_handler![]` macro.

### 2.4. `tauri-plugin-recorder/guest-js/index.ts`
- **Frontend Bindings:**
  - Add `export async function hideOverlay(): Promise<void> { await invoke('plugin:recorder|hide_overlay'); }`

### 2.5. `tauri-plugin-recorder/permissions/`
- **Permissions:**
  - Generate/update the corresponding `hide_overlay.toml` under `permissions/autogenerated/commands/`.
  - Ensure the command is allowed in `permissions/default.toml`.

### 2.6. `tauri-plugin-stt/src/commands.rs` (STT Bridge)
- **Pipeline Setup:**
  - In `setup_record_transcribe_pipeline` (or wherever `RecorderConfig` is instantiated for the bridge), set `hide_overlay_on_recording_stop: Some(false)` on the `rec_config`.

### 2.7. `tauri-plugin-stt/src/desktop.rs` (STT Bridge)
- **Transcription Complete Handoff:**
  - At the end of `process_complete_event`, after transcription logic is finalized (or after an appropriate final display delay if configured), explicitly call `app.recorder().hide_overlay().ok();` to dismiss the overlay.

## 3. Sequence & Data Flow
1. STT app calls `setup_record_transcribe_pipeline` with config mapping to `hide_overlay_on_recording_stop = false`.
2. User ends recording; `stop_recording` finalizes the capture.
3. `stop_recording` evaluates the config and bypasses `sync_overlay_shell`. The state transitions to `Idle` internally, but the window remains visible.
4. STT emits `Transcribing` phase events and updates the web UI inside the still-visible overlay.
5. Transcription succeeds or fails. STT bridge calls `app.recorder().hide_overlay()`, restoring default hidden state.
